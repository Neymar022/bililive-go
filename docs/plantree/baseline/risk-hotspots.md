# Risk Hotspots

## 生产链路风险

- 同源重复入队导致后续失败任务覆盖已完成 metadata。
- 字幕生成、烧录和媒体库归集跨 NAS 与 Mac，多运行时边界需要明确失败语义。
- 成功成品和失败状态可能同时存在，UI 与后续 ingest 不能只看单一信号。

## 知识链路风险

- Bililive-go 如果承担过多知识职责，会和 BiliNote 事实源边界冲突。
- 直接把字幕切块入库会导致时间轴噪音和低质量检索。
- 文档优先生成如果同步阻塞，会拖慢或超时生产同步。
- LanceDB 不可达不应导致知识事实源丢失。

## 存储/runtime 风险

- Mac native/mmap runtime 直接放在易断开的 iSCSI 路径时，可能出现 SIGBUS 或 page-in 错误。
- 大临时视频文件应放在稳定本地 runtime，而不是直接承载在不稳定网络卷上。

## 计划治理风险

- PRD、实际代码、NAS 运行脚本和 BiliNote 仓库可能漂移。
- 后续实现前需要明确哪些能力属于 Bililive-go，本仓库只做生产同步，不做长期知识治理。
